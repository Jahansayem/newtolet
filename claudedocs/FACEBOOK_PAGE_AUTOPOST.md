# Facebook Page auto-post for new listings

Every listing that becomes **approved** on newtolet.com is posted once to the
NewTolet Facebook Page through the Meta Graph API.

## Flow

```
user submits listing ──► properties (status = pending)
                             │ admin approves (admin_set_property_status)
                             │ or auto_approve_properties inserts it approved
                             ▼
trigger trg_properties_queue_facebook_post
   inserts one row into public.facebook_page_posts (status = pending)
   (on conflict do nothing → a listing is never posted twice)
                             ▼
cron on the VPS, every minute:
   POST https://<api>/functions/v1/facebook-page-post   (Bearer FB_POSTER_CRON_KEY)
                             ▼
edge function facebook-page-post
   1. claims up to 5 due rows (pending, next_attempt_at <= now)
   2. re-reads the listing from public_property_catalog (still public? else skipped)
   3. uploads up to 10 photos unpublished  POST /{page-id}/photos  published=false
   4. creates the post                     POST /{page-id}/feed    message + attached_media
      (no photos → message + link to the listing page)
   5. stores fb_post_id (posted) or the error with backoff (5 attempts, then failed)
```

The post never contains the owner's phone number, user id or exact address; it
uses the same public fields as `listing-seo`, plus a link to
`https://www.newtolet.com/listdetails/?id=<uuid>`.

## Server secrets (VPS `/opt/supabase/.env`, never `NEXT_PUBLIC_*`)

| Variable | Value |
| --- | --- |
| `FB_PAGE_ID` | numeric Page ID |
| `FB_PAGE_ACCESS_TOKEN` | **non-expiring Page token** (see below) |
| `FB_GRAPH_VERSION` | optional, default `v24.0` |
| `FB_POSTER_CRON_KEY` | generated by the deploy script (32+ chars) |
| `FB_AUTOPOST_ENABLED` | `true` to post; anything else = queue only (dry run) |

## Meta setup (one time, done by a Page admin)

1. **developers.facebook.com → My Apps → Create app.** Use case: *Manage
   everything on your Page*. App type Business. Name e.g. "NewTolet Poster".
   Connect it to the NewTolet Business portfolio if you have one.
2. **App settings → Basic:** add Privacy Policy URL
   (`https://www.newtolet.com/privacy/` or equivalent), category, app icon,
   App Domains `newtolet.com`. Save.
3. **Use cases → Customize → Permissions:** add `pages_show_list`,
   `pages_read_engagement`, `pages_manage_posts` (and `business_management`
   if the Page lives in a Business portfolio).
   Because you are an admin of both the app and the Page, *Standard access*
   is enough; App Review is not needed for posting to your own Page.
4. **Publish the app (switch to Live).** Posts made by an app in Development
   mode are visible only to people with a role on the app.
5. **Get a non-expiring Page token** (Graph API Explorer):
   1. Select the app, *User Token*, tick the permissions from step 3,
      *Generate Access Token*, choose the NewTolet Page in the dialog.
   2. Exchange the short user token for a long-lived one (*Access Token
      Debugger → Extend Access Token*), or:
      `GET /oauth/access_token?grant_type=fb_exchange_token&client_id={app-id}&client_secret={app-secret}&fb_exchange_token={short-user-token}`
   3. With the long-lived **user** token: `GET /me/accounts` → copy the
      `access_token` and `id` of the NewTolet Page. A Page token obtained
      from a long-lived user token does not expire (Debugger shows
      *Expires: Never*).
6. Deploy (below) with `FB_PAGE_ID` and `FB_PAGE_ACCESS_TOKEN`, check
   `?action=health`, then set `FB_AUTOPOST_ENABLED=true`.

The token is changed if a Page admin changes their password or removes the app;
`?action=health` then fails and pending posts wait (they retry with backoff, then
`failed`; requeue with `update facebook_page_posts set status='pending', attempts=0,
next_attempt_at=now() where status='failed';`).

## Deploy

```bash
# 1. database
psql "$DB_URL" -f supabase/migrations/20261116120000_facebook_page_posts.sql
# 2. function + secrets + cron (Git Bash)
FB_PAGE_ID=... FB_PAGE_ACCESS_TOKEN=... FB_AUTOPOST_ENABLED=false \
  bash scripts/deploy/edge-functions.sh <vps-host> facebook-page-post
# 3. health check on the VPS
curl -s "http://127.0.0.1:8000/functions/v1/facebook-page-post?action=health" \
  -H "Authorization: Bearer $(grep ^FB_POSTER_CRON_KEY= /opt/supabase/.env | cut -d= -f2- | tr -d \')"
# 4. go live
FB_AUTOPOST_ENABLED=true bash scripts/deploy/edge-functions.sh <vps-host> facebook-page-post
```

Existing approved listings are **not** back-posted: the trigger only reacts to
listings that become approved after the migration runs.
